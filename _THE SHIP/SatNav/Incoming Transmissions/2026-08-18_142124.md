```
A confidently documented architectural claim turned out to be transport-
specific, and the narrower truth only surfaced because a live test hit it.

Context: this session built the first code of V2 — a minimal, content-blind
MCP server skeleton in the new folder `_THE VAST UNKNOWN/` at the repo root
(official MCP Python SDK v2, package `mcp` 2.0.0, one placeholder tool
`scan`, committed as 7fb5681). The design was written against the Session
003 review document ("Debris Protocol", published as a Claude artifact on
2026-08-17), which stated flatly that under the MCP spec revision 2026-07-28
"sessions are gone": the `initialize` handshake and `Mcp-Session-Id` were
removed, and therefore cross-call state must ride on explicit handles passed
as ordinary tool arguments — the "identity is a parameter on every call,
never a global in your process" rule.

The empirical result: during the skeleton's round-trip test, a raw JSON-RPC
`tools/list` sent over local stdio was rejected with "Invalid request
parameters" until the client performed the old-style `initialize` /
`notifications/initialized` handshake — after which everything worked, and
the server negotiated protocol version 2025-06-18, i.e. the handshake-era
protocol, not the stateless 2026-07-28 one. So SDK v2 over LOCAL STDIO still
runs sessions. The stateless, no-initialize world the Debris Protocol
describes is real, but it is the Streamable HTTP transport path only.

Why this matters beyond pedantry: the document's design rule survives — 
identity-as-parameter is still correct, and the skeleton's `scan` tool takes
a `guy_handle` argument from line one. But the documented REASONING for the
rule ("the handshake is gone, so there is nothing to hang state on") was
wrong for the transport the project actually runs on today. A rule whose
stated justification is false is fragile: the moment someone notices the
justification doesn't hold locally, the rule itself comes into question,
even though it remains right for the better reason (the same engine must
survive being hosted over HTTP later, where the stateless path is real).

The generalizable lessons. First: spec-revision claims are not global facts;
they are per-transport facts. "The spec removed X" must always be qualified
with which transport path removed it, because SDKs deliberately keep old
paths alive for compatibility. Second: research documents written from
reading (the Debris Protocol was brainstorm-to-spec, no code) carry
confident statements that a twenty-minute empirical probe can falsify or
narrow. The probe here cost two shell commands. Third: when a correction
like this lands, the right move is to preserve the rule and fix the
reasoning — the Debris Protocol's conclusion needed no change, only its
"because" clause. Record corrections against documents rather than silently
building around them, or the document stays authoritative and wrong.
```
