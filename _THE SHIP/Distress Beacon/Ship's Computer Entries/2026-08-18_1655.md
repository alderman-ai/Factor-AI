## Additions

**The run coordinate system.** Annotated tags, namespaced per run, zero-padded:
`RUN_001/PROJECT_START`, `RUN_001/BITER_ATTACK!!`, `RUN_002/BITER_ATTACK!!`. All
three on origin. Every rule in the scheme was **forced by git rather than
chosen** — no spaces because refs are paths on disk, zero-padding because tags
sort alphabetically, `RUN_00N` never a tag on its own because a ref cannot be
both file and directory. That is the good kind of design: the constraint wrote
it.

injected into the *spawned server's* environment, not Claude Code's.

then broken again by the 16:35 unplug and not noticed until this session opened
by obeying an order it could not obey.

## Where the Ship's Computer was wrong

**Designed a hook for a rule that was never true.** The invariant *"a scuttle
commit must delete nothing under `_THE SHIP/`"* is written into two commit
messages and the ritual doc, twice flagged as something that "should be a hook,
not a habit." A full design round was spent on trigger mechanics — three
options, rename detection, where the hook should live — without once checking
whether the rule was true. It isn't: The Guy lives under `_THE SHIP/` and is
meant to die with the run. The operator killed it in one line. *Enforcement
mechanics are the second question. Whether the rule is true is the first.*

**Used a previous session's coinage as shared vocabulary.** "Scuttle" was
deployed throughout as if it were common ground; the operator's answer was *"i
have no idea what the scuttle even is."* That word is load-bearing in
`Commit Ritual.md` — a document meant to be read *before* a reset. A ritual doc
written in vocabulary its only reader does not hold is not a ritual doc.

**Framed the missing `RUN_002/SAME_SHIP_DIFFERENT_DAY` tag as bookkeeping.** It
is not. The operator's correction — that a repair phase belongs between the two
tags — exposed that the coordinate scheme has no vocabulary for the gap it is
currently standing in.

## Signals worth acting on

**The reset-cost instrument is mislabelled.** `Commit Ritual.md` calls
`git diff RUN_00N/BITER_ATTACK!! RUN_00M/SAME_SHIP_DIFFERENT_DAY` the
reset-cost measurement and "what the Ship carried across." That span is the
**repair phase**. Nothing was carried across by that diff — the Ship survived by
not being deleted. Relabelled correctly, a diff that shrinks run over run means
*repairs are getting cheaper*, which is a far better signal and is the operator
improvement metric sitting there unclaimed.

**`_THE SHIP/` mixes durable and disposable in one folder.** That is why no
